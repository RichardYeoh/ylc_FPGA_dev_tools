# office_md 迁移部署说明

面向：需要把工具交付到内网其他计算机的交付人员 / IT 管理员。

---

## 1 迁移包构成

| 文件 | 是否必需 | 说明 |
| --- | --- | --- |
| `office2md.exe` | 必需 | 图形界面主程序 |
| `office2md-cli.exe` | 建议 | 控制台入口，供脚本/拖放使用 |
| `_internal\` | 必需 | 全部运行库，必须与 exe 保持同级 |
| `启动转换工具.bat` | 建议 | 一键启动 |
| `拖放文件转换.bat` | 建议 | 拖放批量转换 |
| `samples\` | 建议 | 部署自检用 |
| `docs\*.md` | 建议 | 说明书 |
| `vendor\`、`src\`、`build\`、`tools\` | 不需要 | 仅开发机重建时需要，交付时可剔除 |

---

## 2 目标机要求

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11 x64（不支持 32 位、不支持 Windows 7） |
| 权限 | 普通用户即可，无需管理员 |
| 运行库 | 无需安装（VC 运行库随系统或随包） |
| Python | 不需要 |
| 网络 | 不需要 |
| Office | 转换 `.doc` / `.ppt`（以及 xlrd 失败的 `.xls`）时需要；`.docx/.xlsx/.pptx` 不需要 |

---

## 3 迁移步骤

1. 在开发机执行打包（若已有发行目录可跳过）：
   ```
   build\build_exe.bat
   ```
   得到 `dist\office2md-1.0.0\` 与 `dist\office2md-1.0.0.zip`（内含 exe 版与源码便携版）。

2. 通过 U 盘 / 内网共享盘把 zip 传到目标机。

3. 在目标机**解压到本地磁盘**，例如 `D:\tools\`。
   - 避免直接从网络路径运行（首次启动慢、易被杀软拦截）；
   - 避免放在含空格/特殊符号的深层路径（非必需，但更稳妥）。

4. 进入 `office2md-1.0.0\office2md-1.0.0-win64\`，双击 `启动转换工具.bat` 或 `office2md.exe`。
   - 若交付的是源码便携版，则进入 `office2md-1.0.0-src-portable\` 双击同名 bat。

5. 按第 4 节做一次自检。

---

## 4 交付自检清单

| # | 检查项 | 期望结果 | 通过 |
| --- | --- | --- | --- |
| 1 | 双击 `office2md.exe` | 图形界面正常打开，无报错弹窗 | ☐ |
| 2 | 日志区 Office 检测 | 显示 `Word=True Excel=True PowerPoint=True pywin32=True` | ☐ |
| 3 | 添加 `samples` 文件夹并转换 | 日志显示 3 个文件全部成功 | ☐ |
| 4 | 检查输出 md | 标题、表格、图片引用正常，图片目录存在 | ☐ |
| 5 | 转换一个 `.doc` 文件 | 成功（耗时 3–6 秒属正常） | ☐ |
| 6 | 转换一个 `.xls` 文件 | 成功 | ☐ |
| 7 | 转换一个 `.ppt` 文件 | 成功 | ☐ |
| 8 | 断网状态下重复 3、5、6、7 | 结果一致，说明无网络依赖 | ☐ |
| 9 | 关闭程序后检查 `temp\` | 无残留大文件 | ☐ |

> 第 5–7 项需要目标机已装 Office；若物流环境暂未装 Office，可只做 1–4 项，并在交付单上注明。

---

## 5 常见交付问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| exe 被杀软误删 | 未签名的自解压程序 | 加入白名单；或改用 `启动转换工具.bat` |
| 双击闪退 | `_internal` 目录缺失或被移动 | 重新完整拷贝目录 |
| 老格式报「未检测到 Office」 | 目标机未装 Office 或安装不完整 | 安装 Office 并重启；确认注册表存在 `Word.Application` |
| 程序目录不可写 | 放在了只读位置（如光盘、部分共享盘） | 拷到本地可写目录 |
| 输出乱码 | 用旧版编辑器打开 md | 用 VSCode / Typora / 新版记事本打开（UTF-8） |
| 首次启动较慢 | 杀软扫描 58 MB 依赖 | 后续启动正常 |

---

## 6 版本升级方式

1. 备份目标机上的 `logs\`（如需保留历史日志）；
2. 删除旧的程序目录（转换结果在别处，不受影响）；
3. 解压新版本目录，重复第 4 节自检。

程序无注册表项、无系统服务，升级即替换目录，不会残留。
